# OBS配信画面（従来のカスタムCSS機能を置換）

ルーム内の「OBS配信画面設定」から編集します。旧CSS生成・コピー画面、配色確定処理、旧表示HTMLは削除しました。OBS表示のファイル名はobs.htmlを継続使用しますが、新しいURLは room と owner を含みます。既存のOBSソースは編集画面の専用URLへ差し替え、幅1920・高さ1080に設定し、旧カスタムCSSを削除してください。URLは誰でも閲覧できる配信表示である旨を編集画面に表示します。

- 左：配信者のアイコン・名前・パート、ルーム名、説明、サイトロゴ。
- 中央：参加者。名前は参加情報から自動取得し、配信用の上書き名・担当パート・ゲスト用5色を編集できます。変更はルーム参加名・アカウント名に影響しません。6人ずつ12秒間隔で表示します。
- 右：completed状態の曲だけをorder順で表示。長い曲名・アーティスト名はスペースのない英字も含め全文折り返し。重複演奏には回数を付記。マスター欠損は行自体を消さず取得できない旨を表示。
- ライト・ダーク、標準・丸ゴシック・明朝、説明とスクロール速度を設定できます。書体は端末のインストール状況に依存します。
- 名前・パートはプレビューで実際のフォント幅を測定し、はみ出し警告時には保存を停止します。配信用の短縮名を設定してください。プレビュー確認前の保存も停止します。
- 一覧が収まれば静止し、長い場合は縦自動スクロール。末尾で3.5秒停止、先頭に戻って2秒停止します。曲の追加・削除・並べ替えで一覧を再構築し先頭から再開します。
- Googleユーザーの画像は本人が設定したuserAvatarsを購読し、ゲストは5色の既定画像です。OBSからアイコンを書き換えることはできません。

obsScenes/ルームID/配信者UID に設定を上書き保存します。画像本体やマイリストはコピーしません。ログイン本人だけが自分の設定を書き込め、他の配信者の設定やルームデータには書き込みません。Google・匿名ゲストのどちらも、自分の配信用設定を持てます。ルームの存在を条件に設定を読み取れるようにし、一覧の読み取りは禁止します。既存のルーム・楽曲・個人データの権限は変更しません。配信表示は匿名認証で既存のルーム参加情報・queue・songsを読み、ルーム参加者として登録しません。

Firebase Sparkの既存Realtime Databaseだけを使用し、課金プラン・Storage・Functions・APIは変更しません。設定は保存後にOBSへ自動反映し、編集画面を閉じても配信表示が独立してルーム情報を監視します。ルーム削除時は人物と曲を消して案内を表示します。

検証：模擬FirebaseとChromiumで、編集→警告→保存→プレビューの統合、配色、Googleアイコン反映、ゲストの画像分離、24完了曲＋予約曲、長文折り返しと自動移動、複数ページ参加者、独立表示への保存設定復元、ルーム削除、モバイル、言語切替を確認。CIは権限テスト後、現行本番ルールをメモリ/一時ファイル内だけで読み取り、エミュレーターの合成データでOBSの閲覧権限を検証してから設定ルールを適用します。本番ルームデータやルール全文はログに出しません。OBS Studio実機での確認は別途必要です。
