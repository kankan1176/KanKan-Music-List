# 直近のFirebaseルール変更範囲

## 管理者の端末操作を無料構成へ変更した際

`/adminClientControl` を追加しました。Googleログインかつ `/admins/<uid> = true` の管理者だけが、アプリのログアウト・キャッシュ削除・ゲスト名変更の指示を書き込めます。一般ユーザーは自分宛ての指示と自分の端末情報に限って読み書きできます。全体へ公開するのは有効設定と全体キャッシュ削除の指示だけです。

## マイリスト代理登録を追加した際

`/users/<uid>/songs` に管理者の参照権限を追加し、各曲の新規作成だけを許可しました。マスターに存在する曲と対象アカウントであること、Keyの形式などを検証します。他人の既存曲の上書き・削除や、プロフィール・設定全体の参照権限は追加していません。本人の従来のアクセス権限は維持しています。

## セットリストの戻す・削除の修正

ルーム・セットリストのアクセスルールは変更していません。本番と同じルールをローカルのエミュレーターに読み込み、合成データのみで一般ユーザー・匿名ゲスト・管理者の戻す・削除・確定を確認しました。本番の個人データやルール全文をログへ出力しません。

画面のトランザクション処理には、Firebaseのローカルキャッシュがまだ空の場合に、データがないと判断して中止する条件がありました。対象ノードを読み込んで監視を維持してから、状態を再確認して書き込むよう変更しました。他の参加者が先に状態を変更した場合の保護は維持します。15秒間データを読み込めない場合は操作を終了し、再試行できるようにします。

確認に使うGitHub Actionsは「Verify live queue permissions without publishing rules」です。ルールを取得してテスト用データベースへ適用するだけで、本番ルールや本番データへの変更は行いません。


## Googleログインユーザーの表示名編集

管理者は `users/$uid/profile/displayName` と、既存の `publicProfiles/$uid/displayName`、`friendProfiles/$uid/displayName` を更新できます。Googleログイン管理者であること、対象がアカウントであること、名前が1〜40文字で空白のみ・制御文字を含まないことを確認します。親プロフィール全体やコードの編集権限は追加しません。

管理画面の「ユーザー操作」で表示名を変更すると、個人設定と既存の公開プロフィールを一括更新します。本人の接続中の画面とルーム表示にも反映し、未接続端末は次回接続時に読み込みます。Googleアカウント本体の名前は変更しません。ルームのアクセス権限は変更しません。


## マイリストのURL共有

`userListShares/$uid` はGoogleログインした本人だけが読み書きできる公開設定です。`publicListShares/$token` は推測困難な48桁のランダムな識別子で参照する公開用スナップショットで、一覧取得はできません。作成・更新・削除は所有者だけが可能です。

共有先で公開するのは表示名、保存済み楽曲の曲名・アーティスト名・ChordWikiリンクと、任意で選んだKey・担当パートだけです。メールアドレスや個人設定は含めません。Key・担当パートは初期状態では非公開です。公開停止で公開用の楽曲・配色を削除し、URLの所有者を保持する非公開の最小レコードだけを残します。停止中の書き込み・閲覧はルールで拒否し、公開再開時のみ同じURLで閲覧できます。URL再発行の画面操作は設けません。共有URLを受け取った人による転送・保存までは取り消せません。

個人リストの保存・ルーム参加・管理者機能の既存権限は変更しません。Cloud Functionsや課金プランの追加はありません。


## 共有ページのデザイン・背景・ジャンル

公開設定とスナップショットに、100文字以内のタイトル、ダーク／ライトを基準とする7色の配色（検索欄の文字色を含む）、背景の重ね色の濃さ（0〜85）を追加します。色は6桁のHEX値だけを許可します。楽曲にはジャンル情報を含め、既存の共有ページは公開マスターからジャンルを補完できます。

背景は16MB以下のJPG/JPEGをブラウザーで1920×1080に調整し、JPEGとして圧縮します。元画像や位置情報等のメタデータはアップロードしません。`userListBackgrounds/$uid` は本人だけが読み書き可能な画像設定です。共有用画像は `publicListBackgrounds/$token` に分離し、有効な共有URL・現在の画像バージョンに限り閲覧を許可します。保存するデータURLは360,000文字以下とし、JPEG形式以外は拒否します。

公開停止時には共有画像を削除します。停止後も本人用の圧縮画像は保持し、再公開時に再利用できます。一覧の検索・ページ送りで同じ背景を取得し直しません。画面全体を固定し、100曲単位の一覧部分だけをスクロールします。


## 公開スイッチ・本人用一覧・設定の上書き

`userListShares/$uid/enabled` を追加します。従来の公開設定は値が未設定なら公開中として扱い、既存URLとの互換性を保ちます。停止時はこの値をfalseにして公開用の楽曲・配色と共有画像を削除し、本人用のURL・タイトル・配色・画像は保持します。停止中は公開スナップショットが残っていても第三者による閲覧を拒否し、所有者自身による古い同期の書き込みも拒否します。再開は同じURLを使用します。

検索欄の文字色 `appearance/searchText` は6桁HEXだけを許可します。背景・配色の変更を保存する際に上書き警告を出し、キャンセル時には保存しません。以前の画像や配色の履歴は作成しません。

本体の左メニューに「マイリストサイト編集」「マイリスト共有」を追加します。未公開の場合はGoogleログインした本人だけが保存済み一覧を閲覧する `mylist.html#mine` を開き、閲覧だけで公開設定は変更しません。既存の楽曲編集用マイリストは残します。規約リンクは本体の既存の利用規約・プライバシーポリシー画面を参照します。

停止中はURL所有者の非公開レコードを保持し、他のユーザーによる同じURLの取得や、所有者レコードの削除を拒否します。共有を停止・再開してもURLの所有者は変わりません。


## フレンドから共有ページへの導線
公開中の共有リストだけ、publicListLinks/ユーザーID に共有トークンを保存します。一覧取得は禁止し、公開停止・所有者不一致の場合は参照できません。既存の公開中リストはルール反映時に所有者と公開状態を確認して補完します。未公開の旧フレンド共有データは公開しません。旧index内の閲覧モーダルは削除し、ルーム用共有同期は維持します。



## 2026-10-21：公開範囲とマスター編集の制限

- 旧 friendSharedLists はGoogle認証された所有者だけが読めます。公開リンクの停止を回避する旧経路として利用できません。本人のルーム内共有用スナップショットと既存データは保持します。
- songs、masterMeta、songEditLogs の一般利用者による直接書き込みを制限します。既存のスキーマ検証は保持します。
- 楽曲編集は songChangeRequests/{songId}/{uid} に承認待ちで保存し、管理者が変更元を確認して承認すると反映します。未承認の申請を本人が差し替えたり、他人の申請を読んだりすることはできません。
- 本番から取得したルールをローカルエミュレーターへ渡し、上記のアクセス検証に成功してから適用します。検証では合成データのみを使用します。
- 無料Spark構成のままで、Functions・課金API・保存データの削除は追加しません。


## 2026-10-21：アカウント情報と描画処理の追加防御

- 本番から取得したルールを基に、匿名・ゲスト・別Googleアカウントから個人プロフィール、メール、登録曲、履歴、管理用ログ等へアクセスできないことを、合成データだけで検証します。
- 今後の編集承認ログでは、管理者のメールアドレスを保存しません。既存ログは削除せず、管理者だけが読める状態を検証します。
- Google表示名がない場合にメールアドレスの一部を参加名へ転用しません。既存の表示名は変更しません。
- キューデータ内の同名フィールドで、検証済みの実際のキューIDが上書きされないようにします。
- 公開中の楽曲一覧は引き続き公開情報です。Python等の収集を完全に防ぐものではありません。App Checkは未登録のため、この変更だけで不正取得対策が有効になったとは扱いません。
