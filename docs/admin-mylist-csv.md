# 管理者によるマイリスト参照・CSV代理登録

## 手順

1. 管理画面の「ユーザー操作」を開きます。
2. Googleログインユーザーのアカウント名をクリックします。
3. 保存済みマイリストを確認し、「マイリスト代理登録」を押します。
4. CSVを選び、「内容確認へ」を押します。
5. 追記・重複・除外の判定を確認し、「確定」を押します。

対象は選択したユーザーです。名前とUIDを画面上部に表示します。ゲストは個人マイリストを持たないため対象にしません。

## CSV

```csv
曲名,アーティスト,Key
ライラック,Mrs. GREEN APPLE,+2
青と夏,Mrs. GREEN APPLE,
```

添付のテンプレートと同じ列順です。Key列は省略でき、空欄は0（原曲）です。値は-5〜+6の整数に対応します。見出しのみの場合は登録できません。UTF-8・UTF-8 BOM・Shift_JISに対応し、最大2MB・5,000データ行です。カンマ・改行・引用符を含むセルは通常のCSV引用形式にしてください。

曲名・アーティストをUnicode正規化し、大文字小文字・空白・句読点の違いを吸収してマスターと照合します。複数の候補がある行は確認画面で登録先を選びます。未選択の行は除外します。似ているだけの別の曲を推測して登録しません。

以下は保存しません。

- 既存マイリストにデータがある曲（既存Key・パート・お気に入りを変更しません）
- CSV内で重複する曲の2行目以降
- マスターに一致しない曲、候補未選択の行
- 曲名・アーティストの空欄、Keyの範囲・形式が不正な行

追加曲は登録済み・指定Key・担当パート未設定・お気に入りなしで保存します。既存データの削除は行いません。本人の画面は再読み込みで反映され、フレンド共有情報は本人の既存の同期処理で更新されます。

## 保存と競合

確定直前にマスターと既存マイリストを再取得します。確認時から照合結果が変わった場合は、更新内容を表示して再度の確定を求めます。各曲はFirebaseのトランザクションと「新規作成だけ」のルールで保存するため、保存中に同じ曲が登録されても上書きしません。

大量のCSVは曲ごとに順次保存します。通信断や権限変更では一部だけ保存される場合があるため、登録結果を追記・競合重複・失敗に分けて表示します。再実行時は保存済み分を除外します。処理中は画面を閉じず、完了を待ってください。

## 権限と公開

Sparkプランと既存のRealtime Databaseを使用し、課金サーバーは追加しません。Googleログインかつ `/admins/<uid> = true` の管理者に限り、`users/<uid>/songs` の読み取りとマスターに存在する新規曲の追加を許可します。他ユーザーのプロフィール・設定全体の読み取り、既存曲の変更・削除の権限は追加しません。本人の既存権限は保持します。

関連ルールはGitHubの「Apply free admin control rules」で、エミュレーターによるアクセス権限・競合テストに成功した場合だけ本番へ反映されます。失敗時には新しい権限を適用しません。
