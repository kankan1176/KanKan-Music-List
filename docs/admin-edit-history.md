# マイリスト編集と楽曲編集履歴

- 管理者ページ → ユーザー操作 → 対象アカウント名 → 各楽曲の「編集」でKey・担当パート・お気に入り・登録状態を変更できます。
- 登録解除はレコードの削除を行わず、解除状態として保存します。「登録解除済みも表示」から再登録できます。CSV代理登録は従来通り追記のみです。
- 公開済みマイリストは、本人が選んだKey・パートの公開設定に従って該当曲だけを同期します。非公開のリストは公開しません。同期に失敗しても保存済みデータは保持し、画面に案内を表示します。
- 一般ユーザーの楽曲編集はGoogleログインが必要です。「この曲の情報を編集」で保存すると即時にマスターへ反映し、編集履歴に記録します。新規楽曲追加の承認手順は維持します。
- 管理者ページ → 楽曲編集履歴で日時・変更項目の前後・編集ユーザー・実行または承認した管理者を確認できます。50件ずつ以前の履歴を追加できます。検索は読み込み済みの履歴を対象とします。
- 履歴の「元に戻す」はその履歴の変更項目だけを戻します。後から対象項目が変更されていた場合は停止します。戻す操作も履歴に残し、履歴自体の書き換えや削除は許可しません。
- 「現在の情報を再編集」または楽曲マスタ画面の楽曲ID入力から、現時点の楽曲情報を編集できます。
- 楽曲・履歴・検索更新用リビジョンは同時に保存します。楽曲リビジョンによって同時更新を検出し、古い画面からの保存を拒否します。検索・絞り込みへの反映は既存の定期更新を利用します。
- 過去の履歴は保存済みの記録を表示し、以前記録されなかった申請者情報を推測しません。

Firebase Sparkの既存構成を使います。Cloud Functionsの追加や課金プラン変更はありません。権限テストでは架空のデータだけを使用します。

検索は曲名・アーティスト・作詞・作曲・編曲・タイアップ作品・検索ワード・BPM・ジャンル・歌唱音源・年情報を共通処理で対象にします。全角半角・大文字小文字を揃え、複数語はANDで照合します。

編集・新規登録の分類は、その時点のマスターにある分類値から選択します。既存曲の未変更の値は保持し、新しい分類名の手入力は受け付けません。PCは3列、タブレットは2列を基本とし、スマートフォンは基本情報／分類／作品・制作のタブを使用します。保存ボタンは入力欄のスクロール領域から分離しています。
