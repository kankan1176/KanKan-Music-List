# クリップボード一括登録の検証（2026-10-15）

ユーザー提供「へにゃリスト - シート1.csv」（215行、曲名・アーティストの2列）と、公開Firebase楽曲マスター27,350曲を使用しました。CSVの内容とマスターのスナップショットはリポジトリへ追加していません。

## 照合結果

- 一致：186曲
- 複数候補からの選択が必要：4曲
- 現行の曲名・アーティスト照合で未一致：25曲
- テストで4曲の候補を選択後、190曲の保存ペイロードを確認

未選択候補が残っている間、登録確認ボタンが無効になることは仕様です。ボタン付近にも理由と件数を表示し、「次の未選択候補へ」で対象行へ移動できるようにしました。候補はテスト上の選択であり、本番で利用者が選ぶ登録先を決定するものではありません。

## 発見・修正した問題

1. 登録結果の「完了」を押しても古い解析画面が残る問題。確認画面への遷移時に解析画面を閉じ、戻る操作を明示的に実装。完了時は一括登録の全画面・解析状態・候補選択状態をリセット。
2. 幅390px・高さ600pxの画面で、説明文に押され登録ボタンが画面外に出る問題。説明・列操作・曲一覧を一つのスクロール領域にまとめ、操作ボタンを下部に固定。
3. 候補を選ぶたびに解析結果のスクロール位置が戻る問題。再描画時にスクロール位置を保持。

## 画面操作の検証

本番と同じPapaParse 5.4.1でCSVを読み、表のコピーを再現するタブ区切りテキストへ変換しました。ブラウザーのクリップボード読み取りをテスト入力に差し替え、実際のボタンをクリックしました。

- 表の読み取り → 列確定 → 215曲の解析
- 4件の未選択候補への移動・選択
- 登録確認 → 解析結果へ戻る → 再度登録確認
- 保存失敗時のエラー表示と再試行
- 190曲の保存先・重複のないID・Key・既存の担当パートとお気に入り状態の保持
- 完了後に古い一括登録画面が表示されないこと
- 再取り込みで前回の候補選択が残らないこと
- ログインアカウント変更時の保存停止
- クリップボード権限エラー時の説明表示
- PC幅1440px、スマートフォン幅390px（高さ844px・600px）での操作ボタンの表示

保存先のFirebase書き込みと認証はモックです。公開マスターは読み取りましたが、利用者の本番マイリストへの書き込みは行っていません。

## 再実行

Playwright、Chromium、PapaParseが利用できる環境で実行します。CLIの第1引数は2列のCSV、第2引数はFirebase形式の公開楽曲マスターJSONです。

```sh
PAPAPARSE_PATH=/path/to/papaparse.min.js node scripts/check-clipboard-process.cjs list.csv master.json
```

PapaparseがNodeモジュールとしてインストールされている場合はPAPAPARSE_PATHを省略できます。ChromiumのパスはCHROMIUM_PATHで指定可能です。既存の照合検証・3言語翻訳検証も通過しました。
