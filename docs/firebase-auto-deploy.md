# 無料構成をGitHubから設定

## 課金する操作は行いません

Cloud Functionsの自動公開は停止しました。`Deploy Firebase admin functions` の過去の失敗実行は再実行しないでください。現在の同名ファイルを手動実行しても、説明の表示だけで公開は行いません。

新しい **Apply free admin control rules** は、既存Realtime Databaseのルールと無料機能の設定だけを更新します。Firebase CLIによる公開、Cloud Functions・Cloud Build・Artifact Registry APIの有効化、Blazeへの変更、請求先の設定は含めません。

## 最初の確認

mainへの反映で自動実行されます。GitHubの **Actions → Apply free admin control rules** を開いてください。

- **緑のチェック**：テストと無料構成のルール適用が完了しています。サイトの管理画面を再読み込みし、ユーザー管理を開きます。
- **赤い×**：実行画面のURLを共有してください。秘密鍵を送る必要はありません。ルールの検証や適用に失敗した場合は、機能を有効化しません。
- 必要に応じて **Run workflow → main → Run workflow** から再実行できます。初回用のチェックは不要です。

以後、無料機能のルール・適用スクリプトをmainへ変更すると、テスト後に自動適用します。画面や画像だけの変更にはルール適用は不要です。通常のサイト公開は従来どおりです。

## 認証とバックアップ

既存の `FIREBASE_SERVICE_ACCOUNT` シークレットを使います。既に付与されているFirebase Realtime Databaseの管理権限を利用します。追加の課金API用権限は不要です。秘密鍵は読み出したり、ソースやログへ表示したりしません。

適用前の本番ルールを取得・バックアップし、個人データの所有者制限やルームのルールを保持したまま `/adminClientControl` だけを追加・更新します。競合した場合は停止します。適用後のルール一致を確認してから、初回だけ機能を有効化します。既にある有効・無効設定は上書きしません。

バックアップはActions実行画面のArtifactsから7日間取得できます。これはデータそのもののバックアップではありません。

## 無料枠について

Sparkプランと、公開GitHubリポジトリの標準Actionsランナーを利用します。プラン変更や追加の有料リソースは作成しません。無料枠には上限があり、上限到達時には機能が制限される可能性があります。

これまで使ったPC内のフォルダーやNode.jsを、運用のために起動しておく必要はありません。
