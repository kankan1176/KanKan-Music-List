# 管理者操作：Sparkプランの無料構成

Firebaseの課金プラン変更やCloud Functionsは使用しません。既存のRealtime Database・匿名認証・Googleログインと、GitHubの公開リポジトリ用Actionsで動作します。Sparkプランを維持してください。無料枠を超えた場合はサービスが制限・停止し、Blazeへの変更を自動では行いません。

## 操作

管理画面の「ユーザー管理」に以下を表示します。

- **アプリからログアウト**：Googleログインしている対象ユーザーのアプリへログアウト指示を送信します。接続中、または次回アクセス時に処理します。Googleの認証トークンを失効・削除する処理は行いません。変更されたクライアントによる無視や、サイト外でのトークン利用を阻止する仕組みではありません。
- **楽曲キャッシュを削除**：対象ユーザー、またはゲストを含む全体に削除指示を送信します。公開楽曲マスターのIndexedDBと、このサイトが管理する公開楽曲レスポンスのキャッシュだけが対象です。マイリスト、個人設定、ログイン情報は保持します。未保存編集を保持するため自動再読み込みはしません。
- **ゲスト名を変更**：ゲスト端末の保存名を変更し、その端末からルームの表示名も更新します。未接続端末へ即時に反映したと表示しません。対象ゲストの端末登録が必要です。Googleユーザーのプロフィール名は変更しません。
- **受信状況**：端末から送られた指示の受信報告を表示します。管理者の送信成功と、端末の実際の受信を区別します。これは監査用の認証ログではありません。

指示はデータベースの変更通知で受信します。認証変更時・オンライン復帰時・画面復帰時と5分ごとの再確認も行います。端末一覧の更新はこれらの確認時です。未ログイン状態でも全体キャッシュ削除は受信できます。個別指示と名前変更には匿名またはGoogle認証のUIDが必要です。ブラウザのサイトデータを全削除して匿名UIDが変わると、旧UID向けの個別指示は引き継がれません。

ログアウト指示以前の認証時刻を持つログインを対象とし、指示後の再ログインは維持します。同じ秒にログインし直した場合は再度ログアウトすることがあるため、少し待って再ログインしてください。管理者自身へのログアウト指示は拒否します。

## 権限制御

新しいデータは `/adminClientControl` に保存します。

- 管理指示を書けるのはGoogleログインかつ `/admins/<uid> = true` の管理者だけです。
- 一般ユーザーは自分宛ての指示・自分の端末登録だけを読み取り、自分の端末登録だけを書き込めます。
- 全体へ公開するのは機能の有効設定と全体キャッシュ削除指示だけです。他人宛てのログアウト指示・名前変更・端末一覧は公開しません。
- ゲスト・アカウントの種別を認証トークンと照合します。一般ユーザーは他人のUIDへ端末登録できません。
- マイリストやルームの既存アクセス条件は変更しません。ルートに包括的な許可・ワイルドカードがある場合は自動適用を停止します。

## 初回設定と自動適用

[無料構成のGitHub設定](firebase-auto-deploy.md)を参照してください。PCでのコマンド入力・ZIP取得・課金API有効化は不要です。

機能を一時停止するには、Firebaseコンソールで `/adminClientControl/config/enabled` を `false` にします。その後のルール更新でも停止状態を維持します。

## 確認手順

1. 管理者とは別のGoogleユーザーとゲストでサイトを開きます。
2. 対象Googleユーザーへログアウト指示を送り、アプリからログアウトし、再ログイン後は継続利用できることを確認します。
3. ゲスト名を変更し、保存名とルーム内表示が変わることを確認します。
4. 個別・全体のキャッシュ削除後も、保存済みマイリストと設定が残ることを確認します。
5. オフラインの端末を戻し、保留中の指示が届くことを確認します。

ブラウザの模擬データを使った操作テストと、既存ルールを保持する変換テストを実施しています。実際のアクセス拒否はGitHubのローカルFirebaseエミュレーターで検証し、合格した場合だけ本番ルールを適用します。開発環境でのエミュレーターバイナリ取得はネットワーク制限で実行できませんでした。本番の適用完了はActionsの結果と管理画面で確認してください。
